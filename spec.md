# Gamebook Authoring Tool — Specification

## Overview

A visual web application for authoring interactive gamebooks organized into **series** and **books**. Each series represents a shared world with its own locations, items, and enemies. Each book within a series has its own story graph made of **acts** containing **nodes**. From any node, the reader makes choices that lead to other beats, encounter items and enemies, and move through acts toward an ending.

The hierarchy is:

```
Series (shared world)
  └── Book 1 (story graph)
        └── Acts → Nodes → Choices
  └── Book 2 (different story, same world)
        └── Acts → Nodes → Choices
```

## 1. Data Model

### 1.1 Series

A series represents a shared world. It owns locations, items, and enemies that can be reused across books. Books within a series inherit these shared entities.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `title` | `string` | Series name (e.g. "The Ashen Cycle") |
| `description` | `string` | Brief description of the world/universe |
| `tone` | `string \| null` | Genre/tone descriptor for AI prompts (e.g. "dark fantasy", "sci-fi thriller") |
| `worldGuidelines` | `string \| null` | Author-written world rules and lore for AI story generation context |
| `createdAt` | `datetime` | Creation timestamp |
| `books` | `Book[]` | Books belonging to this series |

### 1.2 Book

A book is a single gamebook within a series. It has its own story graph but shares world entities with other books in the same series.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `seriesId` | `string` | Which series this book belongs to |
| `title` | `string` | Book title (e.g. "The Haunted Bridge") |
| `description` | `string \| null` | Book-level summary |
| `number` | `number \| null` | Book number in the series (1, 2, 3…) — for ordering in the sidebar |
| `createdAt` | `datetime` | Creation timestamp |
| `acts` | `Act[]` | Acts belonging to this book |
| `nodes` | `Node[]` | All nodes in this book |
| `locations` | `Location[]` | Book-specific locations (see §1.3) |
| `items` | `Item[]` | Book-specific items (see §1.3) |
| `encounters` | `Encounter[]` | Book-specific encounters (see §1.3) |

### 1.3 Shared Entity

Locations, items, and encounters can be **shared** (owned by the series) or **book-specific**. A book can use any of its series' shared entities plus its own book-specific ones.

**Location:**

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `seriesId` | `string \| null` | If set, shared across the series. If null, book-specific. |
| `bookId` | `string \| null` | If set, book-specific (belongs to this book). |
| `name` | `string` | Location name (e.g. "The Crypt") |
| `description` | `string` | Brief flavor text for the location |

**Item:**

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `seriesId` | `string \| null` | If set, shared across the series. |
| `bookId` | `string \| null` | If set, book-specific. |
| `name` | `string` | Item name (e.g. "Silver Dagger") |
| `description` | `string` | What the item is and what it does |
| `effect` | `object` | Optional stat modifiers (e.g. `{ attackBonus: 2 }`) |

**Encounter:**

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `seriesId` | `string \| null` | If set, shared across the series. |
| `bookId` | `string \| null` | If set, book-specific. |
| `name` | `string` | Enemy/event name (e.g. "Skeleton Guard") |
| `description` | `string` | What happens when encountered |
| `stats` | `object` | Optional combat stats (e.g. `{ hp: 10, attack: 4 }`) |
| `recurring` | `boolean` | Can this encounter happen at any node tagged with the same enemy, or only here? |

### 1.4 Node

Every node represents a single story beat.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `bookId` | `string` | Which book this node belongs to |
| `title` | `string` | Short title for the beat (e.g. "The Haunted Bridge") |
| `description` | `string` | Full text of the beat — what the reader sees |
| `locationId` | `string \| null` | Reference to a location (shared or book-specific) |
| `items` | `Item[]` | Items found or obtained at this beat |
| `encounters` | `Encounter[]` | Enemies or events that can occur here |
| `type` | `enum` | `"entry"`, `"beat"`, `"exit"`, `"ending"` |
| `actId` | `string` | Which act this node belongs to |
| `choices` | `Choice[]` | Branching options leading to other nodes (see §1.5) |
| `x, y` | `number` | Position on the visual canvas (author-controlled) |
| `storyText` | `string \| null` | Full prose generated by AI (initially null, filled in Phase 7+) |
| `storyStatus` | `enum` | `"pending"`, `"generating"`, `"complete"`, `"failed"` |
| `storyModel` | `string \| null` | Which model generated the story |
| `storyPrompt` | `string \| null` | The prompt sent (for debugging) |

### 1.5 Choice

A choice lives on a node and points to another node within the **same book**.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `sourceNodeId` | `string` | Node this choice is on |
| `text` | `string` | What the reader sees and clicks (e.g. "Go deeper into the tunnel") |
| `targetId` | `string` | UUID of the destination node (must be in the same book) |

### 1.6 Act

An act groups a set of nodes and provides entry/exit structure within a book.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier |
| `bookId` | `string` | Which book this act belongs to |
| `title` | `string` | Act name (e.g. "Act I — The Call") |
| `order` | `number` | Sequential position (1, 2, 3…) |
| `entryNodeIds` | `string[]` | One or more nodes that readers can enter this act through |
| `exitNodeIds` | `string[]` | Nodes that allow the reader to leave this act (leading to the next act) |
| `nodeIds` | `string[]` | All nodes belonging to this act |
| `hasEndings` | `boolean` | True only for the final act |

**Act constraints:**

- Acts are ordered sequentially within a book. A reader cannot skip ahead.
- Each act (except the final) has **at least one exit node**.
- The final act has **zero exits** — only ending nodes.
- Entry and exit nodes may overlap (an exit node can also be the entry to the next act).
- An act can have **1 to many** entry and exit nodes.

### 2.1 Layout

├──────────┬──────────────────────────────────────────┤

│   - Books│                                           │
│     - Acts│                                          │
│       - Nodes│                                       │
│ - Shared │                                           │
│   - Locations│                                       │
│   - Items │                                          │
│   - Enemies │                                        │
│ - Book   │                                           │
│   - Locs │                                           │
│   - Items│                                           │
│   - Enem.│                                           │
│          │                                           │
├──────────┴──────────────────────────────────────────┤
│  Status / Validation warnings                       │
└─────────────────────────────────────────────────────┘

- **Toolbar** (top): global actions — create a new series, save, export, preview, generate story.
- **Sidebar** (left): tree views organized by hierarchy:
  - **Series** (expandable) → **Books** (expandable) → **Acts** → **Nodes**
  - **Shared** (entities owned by the series, visible to all books) → Locations, Items, Enemies
  - **Book** (entity lists specific to the currently selected book) → Locations, Items, Enemies
- **Canvas** (center): the interactive graph view for the currently selected book.
- **Status bar** (bottom): validation errors.

### 2.2 Canvas

The canvas is an interactive, pan-and-zoom graph view.

**Node rendering:**

- Each node is a rounded rectangle showing its `title`.
- Node appearance varies by `type`:
  - **Entry**: green border, entry icon
  - **Beat**: default border
  - **Exit**: orange border, exit icon
  - **Ending**: red border, flag/trophy icon
- Nodes can be dragged to reposition (`x, y`).
- Connection lines are drawn between nodes based on `choices`.
  - Lines are directed arrows.
  - Hovering a line shows the choice text.

**Canvas actions (toolbar or right-click menu):**

| Action | Description |
|---|---|
| **New Node** | Create a node in the selected act. |
| **Connect From [Node]** | Open the Connect modal with this node as the source. |
| **Connect To [Node]** | Open the Connect modal with this node as the target. |
| **Delete Node** | Remove node and all its connections. |
| **Select Act** | Highlight all nodes in a given act (color-coded by act). |

### 2.3 Connect Modal

When the user clicks **Connect Forward** or **Connect Back** on a node, a modal opens.

```

│  Connect from: "The Haunted Bridge" │
├─────────────────────────────────────┤
│                                     │
│  Choice text:                       │
│  ┌─────────────────────────────┐   │
│  │ Go deeper into the tunnel   │   │
│  └─────────────────────────────┘   │
│                                     │
│  Destination node:                  │
│  ┌─────────────────────────────┐   │
│  ▼ Select a node...             │   │
│  [ The Dark Forest ]            │   │
│  [ The Haunted Bridge ]         │   │
│  [ The King's Throne ]          │   │
│  [ The Hidden Cave ]            │   │
│                                     │
│  [ Connect Forward ]  [ Cancel ]   │
└─────────────────────────────────────┘
```

- **Choice text**: free-text input for what the reader sees.
- **Destination node**: searchable dropdown of all existing nodes **in the same book**.
- **Connect Forward**: creates a `Choice` on the *current* node pointing to the selected destination.
- **Connect Back**: creates a `Choice` pointing back to an earlier node. Same operation, semantic distinction.

**Validation at connect time:**
- A node cannot choose itself.
- A choice cannot target a node in another book.
- If connecting to a node in an earlier act (not using "Connect Back"), a confirmation warning appears.

### 2.5 Sidebar

**Series → Books tree:**

- Expandable/collapsible tree: Series name → Book title → Act → Nodes.
- Clicking a book name switches the canvas to that book's graph.
- Clicking a node name highlights it on canvas.
- "New Book" button on each series.
- "New Act" button on each book.
- "New Node" button on each act.

**Shared entity lists (owned by the series):**

- **Locations** — CRUD for series-wide locations. Visible across all books.
- **Items** — CRUD for series-wide items.
- **Enemies** — CRUD for series-wide encounters.

**Book entity lists (owned by the book):**

- **Locations** — CRUD for book-specific locations.
- **Items** — CRUD for book-specific items.
- **Enemies** — CRUD for book-specific encounters.

### 2.6 Act Editor

A dedicated view/tab for managing act structure within a book:

- List of acts in order (draggable to reorder).
- For each act:
  - Title (editable inline)
  - Entry nodes (click to add from a dropdown of nodes in this book)
  - Exit nodes (click to add from a dropdown of nodes in this book)
  - "Add Ending" button
- "Add Act" button to create new acts.

### 2.7 Preview Mode

A read-only mode that simulates the reader's experience within a book:

- Starts at any chosen entry node.
- Shows node description (or `storyText` if available).
- Presents choices as clickable buttons.
- Tracks inventory (items collected) and combat status (encounter stats).
- At an ending node, shows "The End" with a summary.
- Back button to return to previous node.

### 2.8 Series Management View

A view for managing the series-level configuration:

- **Book listing** — all books in the series, with numbers, titles, and a "Manage" button to open that book's editor.
- **Shared entities** — tabs for Locations, Items, Enemies. These entities are visible to and usable by all books in the series.
- **Series settings** — name, description, tone, world guidelines (used as AI context for story generation across all books).

## 3. AI Pipeline Data (Future — Phases 7+)

The graph authoring is **Phase 1–5**. The AI pipeline is **Phase 7+**, built on top of the same data. This section documents the interfaces now so the data model and API are designed with them in mind.

### 3.1 Story Generation

Each node has a `storyText` field (nullable, distinct from `description`). The `description` is the author's outline/beat summary. `storyText` is the full prose generated by the AI.

| Field | Type | Description |
|---|---|---|
| `storyText` | `string \| null` | Full prose for this node, generated by AI. Initially null. |
| `storyStatus` | `enum` | `"pending"`, `"generating"`, `"complete"`, `"failed"` |
| `storyModel` | `string \| null` | Which model generated the story (for traceability) |
| `storyPrompt` | `string \| null` | The prompt that was sent (for debugging/re-generation) |

**API endpoint:**

```
POST /api/books/:id/generate-story
```

**Request body:**

```json
{
  "nodeIds": ["node-uuid-1", "node-uuid-2"],
  "model": "qwen3-35b",
  "temperature": 0.7,
  "maxTokens": 2000,
  "parallel": true
}
```

**Behavior:** For each node in `nodeIds`, the API sends a prompt to the configured inference endpoint. The prompt includes: node `title`, `description`, `location`, `items`, `encounters`, the **series' `tone` and `worldGuidelines`** (for consistency across books), and context from the previous node's `storyText` (to maintain continuity). The generated text is stored in `storyText`. Progress is returned as a stream or a task ID for polling.

**Context prompt sent to the AI model (conceptual):**

```
Write the story text for the following gamebook beat. Write in second person
("You stand..."), past tense. Tone: dark fantasy.

Series World Guidelines: "In the Ashen Cycle, the sky is always grey with
ash. Magic drains the caster's memory. The world ended 300 years ago in
the Cinder War."

Title: The Haunted Bridge
Location: The Crypt
Description: You arrive at a crumbling stone bridge over a deep chasm.
  A ghostly figure blocks the way. The bridge groans under its weight.
Items: Silver Dagger
Encounter: Skeleton Guard (hp: 10, attack: 4)

Previous beat story text: "You descend into the dark passage, torch flickering..."

Write 300-500 words of prose for this beat. Do not include game mechanics.
Include sensory details and atmospheric description.
```

### 3.2 AI Reader Simulation (Playthrough & Evaluation)

Multiple AI models "play through" a **book** by following choices from a starting node, generating responses at each node, and producing an evaluation at the end.

| Field | Type | Description |
|---|---|---|
| `id` | `string (UUID)` | Unique identifier for this playthrough |
| `bookId` | `string` | Which book was played |
| `model` | `string` | Which model played |
| `startedAt` | `datetime` | When the playthrough started |
| `completedAt` | `datetime \| null` | When it finished (null if still running) |
| `status` | `enum` | `"running"`, `"complete"`, `"failed"` |
| `path` | `PlaythroughStep[]` | The sequence of nodes visited and choices made |
| `evaluation` | `object` | Post-playthrough score and comments |
| `startNodeId` | `string` | Which entry node was used |

**PlaythroughStep:**

| Field | Type | Description |
|---|---|---|
| `nodeId` | `string` | Node visited |
| `choiceId` | `string \| null` | Choice taken (null for entry node) |
| `choiceText` | `string` | The text of the choice taken |
| `modelResponse` | `string \| null` | What the AI model said about this beat |
| `rating` | `object` | Model's self-rating of this beat |

**API endpoints:**

```
POST /api/books/:id/playthroughs
```

**Request body:**

```json
{
  "models": ["qwen3-35b", "llama3-70b", "mistral-large"],
  "startNodeId": "node-uuid",
  "evaluationPrompt": "Rate the narrative coherence, choice meaningfulness, and atmospheric quality on a scale of 1-10.",
  "maxDepth": 50
}
```

**Behavior:** For each model, the API starts at `startNodeId` and iteratively:
1. Reads the node's `storyText`.
2. Presents available choices to the model.
3. The model picks a choice and generates a response about that beat.
4. Records the step.
5. Follows the chosen node.
6. Repeats until an ending node, `maxDepth`, or failure.
7. Generates an evaluation summary.

**Response:** Returns an array of playthrough task objects:

```json
{
  "playthroughs": [
    { "id": "pt-uuid-1", "model": "qwen3-35b", "status": "running" },
    { "id": "pt-uuid-2", "model": "llama3-70b", "status": "running" }
  ]
}
```

**Polling:**

```
GET /api/playthroughs/:id       — status and progress
GET /api/playthroughs/:id/path  — the path taken
GET /api/playthroughs/:id/eval  — the evaluation
```

### 3.3 Evaluation Aggregation

| Field | Type | Description |
|---|---|---|
| `model` | `string` | Which model's evaluation |
| `score.narrativeCoherence` | `number` | 1-10 |
| `score.choiceMeaningfulness` | `number` | 1-10 |
| `score.atmosphericQuality` | `number` | 1-10 |
| `score.branchingQuality` | `number` | 1-10 |
| `comments` | `string` | Free-text evaluation |
| `pathAnalysis` | `object` | Which path was taken, how many alternate paths were available but not taken |

**API endpoints:**

```
GET /api/books/:id/playthroughs    — list all playthroughs
GET /api/books/:id/evaluation      — aggregated evaluation across all models
```

**Aggregated evaluation response:**

```json
{
  "bookTitle": "The Haunted Bridge",
  "seriesTitle": "The Ashen Cycle",
  "playthroughs": [
    {
      "model": "qwen3-35b",
      "path": ["entry-1", "bridge", "tunnel", "crypt", "ending-1"],
      "scores": { "narrativeCoherence": 8, "choiceMeaningfulness": 6, ... },
      "comments": "Strong atmosphere but some choices felt arbitrary..."
    }
  ],
  "aggregate": {
    "narrativeCoherence": 7.3,
    "choiceMeaningfulness": 6.7,
    "atmosphericQuality": 8.1,
    "branchingQuality": 7.0
  },
  "pathCoverage": {
    "totalPaths": 5,
    "pathsEvaluated": 3,
    "unvisitedNodes": ["node-uuid-4", "node-uuid-5"],
    "deadEnds": []
  }
}
```

### 3.4 Assembly / Output Generation

**API endpoints:**

```
POST /api/books/:id/assemble
```

**Request body:**

```json
{
  "format": "pdf",
  "options": {
    "includePlayerStats": false,
    "includeEncounterDescriptions": true,
    "includeItems": true,
    "pageNumbers": true,
    "coverTitle": "The Haunted Bridge",
    "seriesTitle": "The Ashen Cycle"
  }
}
```

**Supported formats:** `pdf`, `epub`, `html`, `txt`

**Behavior:** Collects all nodes with non-null `storyText`, orders them, applies formatting, and generates the output file. Returns a download URL.

**Response:**

```json
{
  "taskId": "assemble-uuid",
  "status": "complete",
  "downloadUrl": "/api/books/123/output/gamebook.pdf",
  "fileSize": 2458624,
  "pageCount": 47
}
```

### 3.5 Inference Configuration

The API reads from a configuration file or environment variable for the inference endpoint(s). No model serving is built into this app.

```yaml
# config.yaml
inference:
  endpoint: "http://localhost:8442/v1/chat/completions"
  api_key: "${LOADCOACH_API_KEY}"
  default_model: "qwen3-35b"
  timeout: 120
  max_retries: 3
```

The app only **sends** prompts and **stores** results. The inference infrastructure is external (LoadCoach or any OpenAI-compatible endpoint).

Each book's data is serialized to a single JSON file (or saved to the database during editing).

```json
{
  "version": 1,
  "series": {
    "id": "series-uuid",
    "title": "The Ashen Cycle",
    "description": "...",
    "tone": "dark fantasy",
    "worldGuidelines": "...",
    "sharedLocations": [ ... ],
    "sharedItems": [ ... ],
    "sharedEncounters": [ ... ]
  },
  "book": {
    "id": "book-uuid",
    "title": "The Haunted Bridge",
    "number": 1,
    "description": "...",
    "acts": [ ... ],
    "nodes": [ ... ],
    "bookLocations": [ ... ],
    "bookItems": [ ... ],
    "bookEncounters": [ ... ]
  }

```

**Operations:**

- **Save**: writes to the database; also offers "Download JSON" button.
- **Load**: "Open JSON file" button reads and parses a project file into the database.
- **Export**: "Export for AI" includes story text and all metadata. "Assemble" generates PDF/EPUB/HTML.

## 5. Validation Rules

The app validates the graph and reports issues in the status bar:

| Rule | Severity | Message |
|---|---|---|
| Every act (except last) has ≥ 1 exit node | Error | "Act II has no exit nodes" |
| Every act (except first) has ≥ 1 entry node | Error | "Act III has no entry nodes" |
| No choice leads to a deleted/invalid node | Error | "Choice on 'Bridge' references missing node" |
| A choice targets a node in another book | Error | "Choice on 'Bridge' targets a node in a different book" |
| Node type is set (defaults to `beat`) | Warning | "Node 'Untitled' has no type set" |
| A choice links to a node in a later act (not an exit) | Warning | "'The Forest' jumps from Act I to Act III" |
| A node has zero choices and is not an ending | Warning | "'The Hall' has no choices — is this intentional?" |
| Cycle detection in non-loop contexts | Info | "This creates a loop — was that intended?" |

## 6. Non-Functional Requirements

| Concern | Requirement |
|---|---|
| **Browser support** | Chrome, Firefox, Safari (latest 2 versions) |
| **Responsive** | Desktop-first; sidebar collapses on narrow viewports |
| **Persistence** | Auto-save to database every 30 seconds + on every change |
| **Undo/Redo** | At least 20 steps of undo/redo for all edits |
| **Performance** | Canvas handles 500+ nodes at 60fps (use Canvas API, not DOM nodes) |
| **State management** | Single source of truth; UI is derived from the data model |
| **Accessibility** | Keyboard-navigable canvas; ARIA labels on all modals |
| **Multi-book** | Switching books does not mix nodes, acts, or choices between books |

## 7. Interaction Flow Summary

```
Author opens app
       │
       ▼
  Create Series (or Load existing)
       │
       ▼
  Add Books to the Series → Enter Book → Create Acts
       │
       ▼
  Add Nodes → Connect Forward/Back → Fill in entities
       │
       ▼
  Manage Shared Entities (series-wide locations, items, enemies)
       │
       ▼
  Repeat: drag nodes, connect more, edit content, manage entities
       │
       ▼
  Preview → play through as a reader
       │
       ▼
  Generate Story (AI) → Run Playthroughs (AI) → Assemble Output
       │
       ▼
  Save / Export
```
