# Gamebook Authoring Tool — Work Plan

## Stack

- **Backend:** FastAPI + SQLAlchemy + PostgreSQL (dev: SQLite, prod: PostgreSQL)
- **Frontend:** Vanilla JS (no framework) + HTML/CSS + Canvas API for the graph
- **DB:** PostgreSQL (production), SQLite (development)
- **Inference:** External OpenAI-compatible endpoint (LoadCoach or similar) — app only sends prompts, does not serve models
- **Deployment:** Nginx + Gunicorn, same machine as the AI infrastructure

---

## Phase 1: Project Scaffold & Data Model

**Goal:** FastAPI backend with models, CRUD endpoints, and a static frontend shell.

### Backend

- FastAPI app with `config.yaml` (inference endpoint, database URL).
- Project structure:

```
app/
  __init__.py          # FastAPI app, lifespan, middleware
  config.py            # Settings from config.yaml + env vars
  models/              # SQLAlchemy ORM models
    series.py          # Series table
    book.py            # Book table (FK to Series)
    act.py              # Act table (FK to Book)
    node.py             # Node table (FK to Book, with story* fields)
    choice.py           # Choice table (FK to Node)
    location.py         # Location table (seriesId + bookId for shared/specific)
    item.py             # Item table (seriesId + bookId)
    encounter.py        # Encounter table (seriesId + bookId)
    playthrough.py      # Playthrough table (FK to Book, Phase 7+)
  schemas/             # Pydantic request/response schemas
  routes/              # API route handlers
    series.py          # Series CRUD + books listing
    books.py           # Book CRUD (scoped to series)
    acts.py            # Act CRUD + node assignment
    nodes.py           # Node CRUD + choices, items, encounters
    locations.py       # Locations (series + book endpoints)
    items.py           # Items (series + book endpoints)
    encounters.py      # Encounters (series + book endpoints)
    playthroughs.py    # Playthrough CRUD (Phase 7+)
    assembly.py        # Assembly/export (Phase 7+)
  services/            # Business logic
    inference.py       # HTTP client to external inference endpoint
    validation.py      # Graph validation rules
    playthrough.py     # AI playthrough orchestration (Phase 7+)
    assembly.py        # PDF/EPUB/HTML generation (Phase 7+)
  static/              # Frontend files (HTML, CSS, JS)
  templates/           # HTML templates (minimal)
migrations/            # Alembic migrations
tests/                 # Unit + integration tests
requirements.txt       # Dependencies
config.example.yaml    # Template config
```

- SQLAlchemy models with relationships defined in `models/`. Use `uuid` as primary keys.
- Pydantic schemas in `schemas/` for request validation and response serialization.
- Implement REST API endpoints (OpenAPI auto-generated by FastAPI):

| Resource | Endpoints | Notes |
|---|---|---|
| Series | `GET /api/series`, `POST /api/series`, `GET /api/series/:id`, `PUT /api/series/:id`, `DELETE /api/series/:id`, `POST /api/series/:id/export` | Full CRUD + JSON export |
| Books | `GET /api/series/:id/books`, `POST /api/series/:id/books`, `GET /api/books/:id`, `PUT /api/books/:id`, `DELETE /api/books/:id` | Scoped to series |
| Acts | `GET /api/books/:id/acts`, `POST /api/books/:id/acts`, `PUT /api/books/:id/acts/:id`, `DELETE /api/books/:id/acts/:id` | Scoped to book |
| Nodes | `GET /api/books/:id/nodes`, `POST /api/books/:id/nodes`, `PUT /api/books/:id/nodes/:id`, `DELETE /api/books/:id/nodes/:id` | Returns full node with nested choices, items, encounters |
| Choices | `POST /api/books/:id/nodes/:id/choices`, `DELETE /api/books/:id/choices/:id` | Scoped to node, must be in same book |
| Locations | `GET /api/series/:id/locations`, `GET /api/books/:id/locations`, `POST`, `PUT`, `DELETE` | Series-level (shared) + book-level endpoints |
| Items | `GET /api/series/:id/items`, `GET /api/books/:id/items`, `POST`, `PUT`, `DELETE` | Series-level (shared) + book-level endpoints |
| Encounters | `GET /api/series/:id/encounters`, `GET /api/books/:id/encounters`, `POST`, `PUT`, `DELETE` | Series-level (shared) + book-level endpoints |

- Each node endpoint returns the **full** node object including nested choices, items, and encounters in a single response. The frontend does not need to make separate calls to build the canvas.
- Validation on create/update using Pydantic models — required fields, enum constraints.
- Validate that choices are within the same book (server-side).
- Project export downloads the full project (series + selected book) as a `.json` file.
- Project import reads a `.json` file and creates/updates all data.

### Frontend Shell

- Single HTML page served by FastAPI (via `app.static`).
- Three-column layout: sidebar | canvas placeholder | status bar.
- Sidebar renders a flat list of acts and nodes (fetches from API, no interactivity yet).
- Canvas area shows a placeholder "Graph view coming soon" div.
- Basic nav bar with "Save", "Load JSON", "New Series" buttons.
- **Deliverable:** You can create series, books, nodes, locations, items, encounters via a simple HTML form, save to the database, and see them listed in the sidebar (Series → Books → Acts → Nodes).

**Milestone:** CRUD works. The data pipeline is solid. The OpenAPI docs at `/docs` let you test every endpoint in the browser.

## Phase 2: Graph Canvas (Core UX)

**Goal:** The interactive node graph — drag nodes, draw connections, edit content.

### Canvas Implementation

- **Canvas API** (not DOM nodes) — target 500+ nodes at 60fps.
- Pan (middle-click drag or space+drag) and zoom (scroll wheel).
- Nodes rendered as rounded rectangles with title text.
- Color coding by node type: green=entry, default=beat, orange=exit, red=ending.
- **Connections:** directed arrows between nodes using bezier curves.
- Drag a node to reposition — `node.x, node.y` coordinates saved to the database on drag end (debounced).

### Connect Forward / Connect Back

- Right-click a node → "Connect Forward" or "Connect Back" → modal opens.
- Modal has:
  - Choice text input field.
  - Searchable dropdown of all nodes to pick as destination (**same book only**).
  - "Connect Forward" / "Connect Back" button.
- On submit: creates a Choice on the source node pointing to the target node.
- Canvas immediately redraws with the new connection line.

### Node Edit Modal

- Double-click a node → edit modal appears.
- Editable fields: title, description (textarea), type (select), location (dropdown showing **shared** and **book-specific** locations), act (dropdown).
- Sections for items and encounters (showing shared + book-specific) with add/remove buttons.
- Save updates the node via PUT.

### Visual Organization

- "Select Act" button in toolbar highlights all nodes in that act with a colored halo/border.
- Different act colors so you can see act groupings on the canvas.
- **Book switching:** clicking a different book in the sidebar clears the canvas and loads the new book's graph.

**Milestone:** You can build a connected story graph visually — drag nodes, connect them, edit content. This is the first genuinely useful version of the tool.

## Phase 3: Act Management

**Goal:** Proper act structure with entry/exit control and validation.

### Act Editor View

- Dedicated "Acts" tab or view.
- Shows acts in order with draggable reordering handles.
- Each act shows:
  - Title (editable inline).
  - List of its nodes.
  - Entry node selectors (click to add from the act's nodes).
  - Exit node selectors.
  - "Add Ending" button.
- "Add Act" button to create new acts.

### Validation Engine

- Background validation runs on every save/change (both frontend and backend).
- Rules checked:
  - Every act (except last) has ≥ 1 exit node → Error.
  - Every act (except first) has ≥ 1 entry node → Error.
  - Choice references a missing node → Error.
  - Choice targets a node in another book → Error.
  - Node has no type set → Warning.
  - Choice jumps to a later act without passing through an exit → Warning.
  - Node has zero choices and is not ending → Warning.
- Results shown in the status bar (red for errors, yellow for warnings, blue for info).
- Validation endpoint: `GET /api/projects/:id/validate` returns all issues.

### Act Entry/Exit Flow

- Exit nodes get a visual indicator (arrow icon).
- Exit nodes connecting to the next act are highlighted with a different line color.
- Prevent choices that jump beyond one act forward (with a warning override option).

**Milestone:** Acts are properly managed and validated. The graph has structure.

## Phase 4: Preview Mode (Reader Experience)

**Goal:** Play through the gamebook as a reader would experience it.

### Preview Runner

- "Preview" button opens a full-screen overlay or new tab.
- Starts at any chosen entry node (dropdown to pick starting node).
- Shows the node's description.
- Presents choices as clickable buttons below the text.
- Tracks:
  - **Inventory** — items collected along the path (shown as a panel).
  - **Current location** — the node title.
- At an ending node, shows "The End" with a summary.
- "Back" button to return to the previous node.

### Combat/Encounter System (Basic)

- If a node has encounters, clicking "Continue" triggers an encounter.
- Simple stats display: enemy name, hp, attack.
- Player stats: hp, attack (basic defaults, extendable).
- Simple combat resolution: player attack vs enemy attack, reduce hp, track death.
- Minimal — no dice mechanics yet, just stat comparison.

**Milestone:** You can author a story and actually play it through. The first version that feels like a gamebook tool.

## Phase 5: Polish & Export

**Goal:** Refinement, auto-save, undo/redo, project portability.

### Auto-Save

- Debounced save to database every 30 seconds + on every change.
- Visual indicator: "Saved" checkmark in the status bar.

### Undo/Redo

- Undo stack in the frontend state manager.
- Track operations: create node, delete node, move node, create choice, edit content, connect, disconnect.
- At least 20 steps.
- Keyboard shortcuts: Ctrl+Z / Ctrl+Shift+Z.

### Export Formats

- JSON export (already works).
- PDF export of the project — each node as a page with choices, items, encounters.
- "Export for AI" — includes story text and all metadata for the pipeline.

### Accessibility & Polish

- Keyboard navigation on the canvas (tab through nodes, arrow keys to pan).
- ARIA labels on all modals and buttons.
- Responsive layout: sidebar collapses on narrow viewports.
- Loading states and error handling for API failures.
- Confirmation dialogs for destructive actions.

**Milestone:** The tool is polished, reliable, and portable. Ready for daily use.

## Phase 6: Inference Integration (Bridge)

**Goal:** Connect the app to the external inference endpoint so the AI pipeline data is ready.

### Configuration

- Read inference endpoint from `config.yaml`:
  ```yaml
  inference:
    endpoint: "http://localhost:8442/v1/chat/completions"
    api_key: "${LOADCOACH_API_KEY}"
    default_model: "qwen3-35b"
    timeout: 120
    max_retries: 3
  ```
- Environment variable override for `api_key`.

### Inference Service

- `services/inference.py` — HTTP client that sends chat completions to the configured endpoint.
- Standard OpenAI-compatible request/response format.
- Handles timeouts, retries with exponential backoff, and error mapping.
- Logs all prompts and responses for debugging.

### Node Story Status UI

- In the Node Edit modal, add a "Generate Story" button (disabled if no model selected or endpoint not configured).
- Visual indicator on nodes showing `storyStatus` (pending = gray dot, generating = spinning icon, complete = green check, failed = red X).
- In the sidebar, show story status alongside node names.

**Milestone:** The app can talk to the inference endpoint. Nodes can have their story status tracked. The pipeline data structures are in the database, but the actual generation/playthrough features come next.

## Phase 7: Story Generation

**Goal:** AI writes story text for nodes.

### API Endpoint

```
POST /api/projects/:id/generate-story
```

**Request body:**

```json
{
  "nodeIds": ["node-uuid-1", "node-uuid-2"],
  "model": "qwen3-35b",
  "temperature": 0.7,
  "maxTokens": 2000,
  "parallel": true
}
```

### Behavior

For each node, the API:
1. Builds a prompt from `title`, `description`, `location`, `items`, `encounters`, the **book's series** `tone` and `worldGuidelines` (for consistency), and the previous node's `storyText` (for continuity).
2. Sends the prompt to the configured inference endpoint.
3. Stores the response in `storyText`, updates `storyStatus` to `complete`.
4. If it fails, sets `storyStatus` to `failed` and logs the error.
5. Returns progress (task ID for polling or streaming response).

### UI

- "Generate Story" button in toolbar — generates for all nodes in the selected act.
- "Generate Story" per-node action in the context menu.
- Progress indicator showing which nodes are generating / complete / failed.
- "Regenerate" button for individual nodes.

**Milestone:** AI generates story text for nodes. The author can review, edit, and regenerate.

## Phase 8: AI Playthrough & Evaluation

**Goal:** Multiple AI models play through the gamebook, track their paths, and produce evaluations.

### API Endpoints

```
POST /api/projects/:id/playthroughs    — start playthroughs
GET  /api/projects/:id/playthroughs    — list playthroughs
GET  /api/projects/:id/evaluation      — aggregated evaluation
GET  /api/playthroughs/:id/path        — a single playthrough's path
GET  /api/playthroughs/:id/eval        — a single playthrough's evaluation
```

### Behavior

For each model requested:
1. Starts at the chosen entry node.
2. Reads the node's `storyText`.
3. Presents choices to the model.
4. Model picks a choice, generates a response about the beat.
5. Records the step (node, choice, model response).
6. Follows to the next node.
7. Repeats until ending node, `maxDepth`, or failure.
8. Generates an evaluation summary.

### UI

- "Run AI Playthrough" button in toolbar.
- Modal: select models (multi-select from configured list), select entry node, set evaluation prompt, set max depth.
- Shows running playthroughs with status (running/complete/failed).
- "View Path" button for each playthrough — shows the node sequence on the canvas.
- "View Evaluation" button — shows scores and comments.
- Aggregated evaluation view — side-by-side comparison of all models.

### Evaluation Metrics

| Metric | Scale | Description |
|---|---|---|
| `narrativeCoherence` | 1-10 | Does the story make sense from start to finish? |
| `choiceMeaningfulness` | 1-10 | Did choices feel consequential, not arbitrary? |
| `atmosphericQuality` | 1-10 | Was the tone and mood consistent and engaging? |
| `branchingQuality` | 1-10 | Did the branching structure create interesting variety? |

### Path Coverage

- Shows which nodes were visited across all playthroughs.
- Identifies unvisited nodes (dead ends, unreachable beats).
- Shows which paths each model took.

**Milestone:** You can run multiple models through the gamebook and get structured evaluations. You can see which paths are covered and which are not.

## Phase 9: Assembly / Output Generation

**Goal:** Generate formatted output from the generated story text.

### API Endpoints

```
POST /api/projects/:id/assemble
GET  /api/projects/:id/output/:format  — download generated file
```

**Request body:**

```json
{
  "format": "pdf",
  "options": {
    "includePlayerStats": false,
    "includeEncounterDescriptions": true,
    "includeItems": true,
    "pageNumbers": true,
    "coverTitle": "The Haunted Bridge"
  }
}
```

**Supported formats:** `pdf`, `epub`, `html`, `txt`

### Behavior

1. Collects all nodes with non-null `storyText`, ordered by act and node position.
2. Applies formatting based on options (cover, page numbers, encounter descriptions, items).
3. Generates the output file.
4. Stores it in a project-specific output directory.
5. Returns a download URL.

### UI

- "Assemble Output" button in toolbar.
- Modal: select format (tabs: PDF, EPUB, HTML, TXT), configure options.
- Progress indicator during generation.
- Download link when complete.

**Milestone:** The full pipeline works: author → AI generates stories → output is a formatted book.

## Phase 10: Extensions (Future)

**Not in MVP scope:**

- **Combat engine upgrade:** dice-based resolution, skill checks, inventory effects.
- **Multi-save:** save multiple versions, compare diffs.
- **Collaboration:** real-time multi-user editing (WebSockets + CRDTs).
- **Templates:** pre-built act structures, encounter templates, location presets.
- **Import:** from Twine `.twine` files or other gamebook formats.
- **Character sheets:** player stats tracked across the story.
- **Random encounter tables:** per-location encounter pools with weights.
- **Model comparison dashboard:** visualize which model performed best on which aspects.
- **A/B testing:** run two playthroughs with different evaluation prompts and compare.
