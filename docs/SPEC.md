## 1. Core Principles

1. **One rules engine, many consumers.** The in-app player, bots, LLM players, validation,
   and the print renderer all use the same pure, deterministic engine and the same
   expression language. Nothing re-implements rules ad hoc.
2. **Prose is tier-agnostic; mechanics are rendered.** The LLM writes narrative only.
   Mechanical text ("ORC — SKILL 7 STAMINA 6. If you win, turn to 212") is *generated by the
   renderer* for the chosen tier and output format. This is what makes layered tiers and
   three output formats feasible.
3. **Everything printable.** Any rule construct the engine supports must have a pencil-and-dice
   rendering. Constructs that can't be tracked by hand (e.g. "visited node X") compile to
   printable equivalents (tick boxes / codewords / split sections) or raise a validation issue.
4. **Determinism.** Every run is seeded; every dice roll is an event. Any playthrough —
   human, bot or LLM — can be replayed exactly.
5. **Referential integrity, always queryable.** "Where is this item used?" "Which nodes set
   flag RAVEN?" are first-class queries backed by an index, not string searches.
6. **No Save button.** Every edit persists immediately; undo/redo and named checkpoints
   protect the author.

## 2. Domain Model

### 2.1 Overview

```
Series ─┬─ StyleGuide
        ├─ RuleSystem ── Tier (basic → medium → advanced, inherited)
        │                 ├─ StatDef, TestDef, SkillDef/ClassDef, SlotDef
        │                 └─ CombatProcedure (hooks)
        ├─ Enemy (stat formulas per tier-stat)       ─┐ scope: series or book
        ├─ Item                                       │
        ├─ RandomTable                                │
        ├─ Lore: Character, LoreEntry (location/faction/glossary/history)
        └─ Book ─┬─ Act ─┬─ ActOutline + StoryBeat[]
                 │       └─ Node ─┬─ TextVariant[] ── ProseVersion[]
                 │                ├─ on_enter Effect[]
                 │                ├─ Encounter[] (fixed group | table)
                 │                ├─ Shop?
                 │                └─ Choice[] ── Outcome[] → target Node
                 ├─ SectionNumbering (pins + seed + stable map)
                 └─ Playtest batches / runs / steps
RefIndex (derived): (source, target type, target key/id, role, field, qty) per reference.
```

Primary keys are UUIDv7 (sortable). Every content entity also has a human **`key`**
(e.g. `a1_bridge`, `goblin_scout`, `RAVEN`) used in expressions, exports and prompts. Keys
match `^[A-Za-z][A-Za-z0-9_]{0,63}$` (identifier-like so gbx needs no quoting; hyphens would
read as minus), can't look like dice (`d6`) and avoid reserved words. Convention: stats,
flags and skills UPPER_CASE; entities lower_snake_case. Keys are unique per scope (series,
book for nodes/acts) and renaming one rewrites every reference (via RefIndex).

**Scope:** Enemies, items, tables, characters and lore always carry `series_id`; `book_id`
is NULL for shared entities or set for book-specific ones. Keys are unique per series across
both scopes, so a key in an expression is never ambiguous.

### 2.2 Story structure

**Book**: `number, title, synopsis, style_overrides, start_node_id`.

**Act**: `order, title, color, summary` + outline (§2.7).

**Node**

| Field | Notes |
|---|---|
| `key`, `title` | Human handle + display title |
| `act_id` | Required |
| `is_act_entry`, `is_act_exit` | Not exclusive. The book start is `book.start_node_id`. |
| `ending` | null, or `{kind: victory\|death\|dead_end, grade?: good\|neutral\|bad\|secret, label}` |
| `beat_notes` | Author's notes for this beat (LLM input) |
| `summary` | One-line summary (auto-suggested from approved prose, editable) |
| `location_id`, `characters[]` | Lore links (drive prompt context) |
| `on_enter` | `Effect[]` (each effect has `once`, default true for gains) |
| `canonical_predecessor_id` | Auto-chosen (shortest path from book start), author-overridable |
| `style_override` | e.g. word range, mood |
| `section_pin` | Optional fixed section number |
| `items[]` | Items found here (optional pickup): `{item_id, qty}` rows |
| `is_shop`, `shop_sell_rate`, `shop_items[]` | Shop: `{item_id, price, stock?}` rows |
| `x, y`, `collapsed` | Canvas layout |

**Text variants**: a node has ≥1 `TextVariant {condition?, label, priority}`. The default
variant has no condition. Example: *First visit* / *Returning (visits ≥ 2)* / *Has codeword
FIRE*. At runtime the highest-priority matching variant is shown. For print, variants compile
to split sections (see §6.3).

**Choice**

| Field | Notes |
|---|---|
| `order`, `label` | What the reader sees |
| `condition` | Expression; null = always available |
| `unmet_display` | `hide` \| `show_disabled` (digital only; print always uses "If you…, turn to") |
| `print_text` | Author override of the auto-rendered print phrasing |
| `min_tier` | Choice exists only at/above a tier (optional) |
| `effects` | `Effect[]` applied when taken (e.g. pay 5 gold) |
| `kind` | `goto` \| `roll` \| `test` \| `combat`, with `dice` / `test` / `encounter_id` + `flee_allowed` |
| `outcomes[]` | Rows: `{key, target_node_id, range_lo?, range_hi?}` — real FKs, so the graph is queryable |

Outcome keys per kind:

```yaml
goto:    [default]
roll:    free keys, each with a range; ranges must cover the dice range exactly (dice default 2d6)
test:    [success, failure]                # test = a TestDef key from the rule system
combat:  [win, lose] (+ flee if flee_allowed)   # encounter_id = one of this node's encounters
```

**Act-link rules** (validated): a choice whose target is in a different act must originate
from an `is_act_exit` node and target an `is_act_entry` node of the **next** act. Every
non-final act has ≥1 exit; every act after the first has ≥1 entry.

### 2.3 Expression language (`gbx`)

One small, safe, parsed language (never Python `eval`) used for: dice, stat formulas,
conditions, effect amounts, combat hooks. Stored as source text and parsed on demand (fast);
the AST serialises to JSON for the game bundle.

```
2d6 + player.SKILL                    # dice + refs
8 + level * 2 + floor(level / 3)       # enemy stat formula
has(potion) and GOLD >= 5              # condition (bare stats mean the player's)
flag(RAVEN) or skill(TRACKING)
visits(a1_bridge) >= 2 and tier >= medium
max(1, damage - target.ARMOR)          # combat hook
natural == 12 ? damage * 2 : damage    # ternary
```

- Types: number (exact fractions), bool, tier. Results that must be integers round down;
  `floor ceil round` make rounding explicit (round = half up) and the checker warns about
  unrounded division. Functions: `min max floor ceil round clamp abs` and reference
  functions `has count equipped flag skill class visits`. Contexts expose different names
  (`level` in enemy formulas, `roll` in tests, `damage/natural/attacker/target` in combat
  hooks); dice are disallowed in conditions and enemy formulas.
- Analysis: value ranges (interval arithmetic) and exact distributions for dice sums, used
  for roll-coverage validation and odds display.
- Every AST node has a **print renderer** ("If you possess a Rope and at least 5 Gold
  Crowns…"), and the editor shows that rendering live.
- Static checks: unknown refs, type errors, tier-unavailable stats, non-printable constructs.
- Kept deliberately small so a TypeScript evaluator (for the standalone player) is cheap.

**Effects** are structured, not free expressions:
`modify(stat, expr) · set(stat, expr) · give(item, qty) · take(item, qty) · equip(item) ·
set_flag(F) · clear_flag(F) · learn(skill)` — each with `once` (default: true for gains),
`min_tier`, `print_text` and a print renderer. Currency is a rule-system resource, so gold
changes are `modify(GOLD, …)`.

### 2.4 Mechanics (RuleSystem)

A series has ≥1 RuleSystem (one active; extras allow balance experiments). A RuleSystem
has an ordered tier chain; each tier declares only what it **adds or overrides**; the
effective tier is the merge of its ancestors. The UI shows inherited items greyed.

```yaml
tier: basic
stats:
  - {key: SKILL,   label: Skill,   initial: "1d6 + 6", min: 0, max_is_initial: true}
  - {key: STAMINA, label: Stamina, initial: "2d6 + 12", min: 0, max_is_initial: true, defeat_at: 0}
  - {key: LUCK,    label: Luck,    initial: "1d6 + 6"}
resources: [ {key: GOLD, label: Gold Crowns, initial: "10"} ]
tests:
  - {key: luck, label: Test your Luck, roll: "2d6", success: "roll <= player.LUCK",
     after: ["modify(LUCK, -1)"]}
combat:
  attack:      { player: "2d6 + player.SKILL", enemy: "2d6 + enemy.SKILL" }
  on_hit:      { damage: "2", stat: STAMINA }
  multi_enemy: sequential
  flee:        { allowed: true, cost: "modify(STAMINA, -2)" }
---
tier: medium            # inherits basic
stats:  [ {key: ARMOR, label: Armour, initial: "0"} ]
slots:  [ weapon, body, shield ]
combat:
  damage_hooks: [ "max(1, damage - target.ARMOR)" ]
---
tier: advanced          # inherits medium
classes: [ {key: ranger, skills: [TRACKING, ARCHERY]}, ... ]
skills:  [ {key: TRACKING, label: Tracking, description: ...} ]
combat:
  damage_hooks: [ "natural == 12 ? damage * 2 : damage" ]
  enemy_abilities: true
```

Combat is a **fixed procedure with expression hooks** — expressive enough for
FF/Lone-Wolf/d20 styles, constrained enough to always be printable:

1. Each round the player rolls `player_attack` against their current target (the first
   living enemy) and each *fighting* enemy rolls `enemy_attack` (sequential: only the
   first living enemy fights; simultaneous: all living enemies fight).
2. If the player beats their target's roll, the target takes damage; if an enemy beats
   the player's roll, the player takes damage; ties and the player beating a non-target
   enemy do nothing.
3. Damage starts at `damage` (default 2) and passes through `damage_hooks` in order;
   each hook sees `damage`, `natural` (the attacker's dice faces), `attacker`, `target`.
   The result (rounded down, never negative) reduces `damage_stat`, clamped at its minimum.
4. A side is defeated at `defeat_at` of the damage stat. Outcomes: `win`, `lose`,
   `flee` (if allowed; `flee_cost` effects apply). 200 rounds without a result is a
   stalemate and counts as `lose`.

Also defined per rule system: character creation (roll stats, choose a class with skills,
stat bonuses and gear, starting gear; §2.4a), experience and levels (§2.4a), equipment slot rules, adventure-sheet layout (for print), and the
author-written rules chapter text per tier.

### 2.4a Character creation & progression

Creation runs in a fixed order:
1. Roll every player stat's `initial`.
2. Choose a class: grant its skills and apply its **stat bonuses**. A bonus is
   `{stat, amount: gbx}`; it adds to the stat, and to its maximum when the maximum is the
   starting value.
3. Log `character_created`.
4. Give the **starting gear**: the tier chain's `starting_items` (they accumulate, root
   first), then the class's. Each entry is `{item, qty, equip}`, and `equip` puts the item
   in its slot when the tier uses that slot.

```yaml
tier: medium
stats: [ {key: XP, label: Experience, initial: "0"}, {key: LEVEL, label: Level, initial: "1", min: 1} ]
progression:            # each field left unset inherits from the parent tier
  xp_stat: XP
  level_stat: LEVEL
  xp_award: "max(1, 10 + 5 * (enemy_level - level))"   # per enemy beaten
  xp_to_next: "100 * level"                            # no dice
  max_level: 10
  level_up: [ {stat: STAMINA, amount: "2"}, {stat: SKILL, amount: "level % 3 == 0 ? 1 : 0"} ]
starting_items: [ {item: potion, qty: 2} ]
```

**Choosing a class in the story.** A tier's `class_choice` is `start` (the default) or
`story`; it inherits like the other settings. At `story` tiers no class is picked at
creation. Instead:
- A `choose_class` effect (optional `classes` subset; once by default) sets
  `class_pending`. It can go on node arrival, a choice, a test or an item.
- While a class is pending, the only actions are `choose_class <key>` ("Become a …").
- Picking applies the class's skills, bonuses and gear, and logs `class_chosen`.
- A reader who already has a class is never asked again.

Print says "Later in your adventure you will be asked to choose one of these" and turns the
effect into "Choose your class now: …".

**Experience.** Winning a fight (not fleeing) evaluates `xp_award` once per enemy in it,
with `enemy_level` and `level` (the reader's level stat). The total goes to `xp_stat`
(`xp_gained` event). Levelling is on when `xp_stat`, `level_stat` and `xp_to_next` are set.

**Levelling up.** After any change to the XP stat (a fight, or an effect such as
`modify XP 50`), the engine repeats:
- While XP ≥ `xp_to_next(level)` and the level is below `max_level` and the level stat's
  maximum, spend that much XP, add 1 to the level (`level_up` event), then apply each
  `level_up` bonus with `level` = the new level.
- A non-positive or broken `xp_to_next` stops levelling.
- At most 100 levels are gained per change.

Item modifiers (§2.6) apply to every item category, so equipment and carried items alike
can change battle stats.

Print explains all of this in the "Your Character" section, and prints enemy levels in
fight tables when fights give XP.

### 2.5 Enemies, encounters, random tables

**Enemy**: `key, name, description, tags, lore_link, stat_formulas{stat_key: gbx}`,
`abilities[]` (advanced), `loot` (items or table), `default_level`.
Formulas only need values for stats active in the tier being played; missing formulas for
an active tier stat are validation errors. The editor shows a live L1–L10 table + chart per
tier.

**Encounter** (on a node): `mode: fixed | table`, `group: [{enemy, level, count}]`,
`fight: simultaneous | sequential`, or `table_id`. Combat choices reference an encounter.

**RandomTable**: `dice expr, entries[{range, result}]` where result is an enemy group, item
grant, gold, or nothing. Reusable across nodes.

### 2.6 Items & shops

**Item**: `key, name, description, category (equipment | consumable | key | treasure),
slot?, stackable, max_stack, value, uses?, modifiers[{stat, expr, min_tier}],
use_effects[], lore_link`. Modifiers apply to any category: an item with a slot counts while
equipped, and any other item counts while carried. Currency is a rule-system resource
(GOLD), not an item. Node arrival and choice effects have a quick money field.

**Shop** (on a node): `buy[{item, price, stock?}]`, `sell_rate`.

**Item page** shows auto-computed totals from the RefIndex: every node placement, random
table entry, shop stock, enemy loot, and every condition/effect referencing it — each with
act, node link, quantity and context ("found", "reward", "shop", "required by choice").

### 2.7 Lore & outline

- **Character**: name, role, appearance, voice/speech notes, motivations, secrets,
  relationships `[{character, kind, notes}]`, appearances (derived from node links).
- **LoreEntry**: `type: location | faction | history | glossary | other`, name, body (markdown),
  typed fields. Nodes link to a location and characters.
- **ActOutline**: act summary + ordered **StoryBeats** `{title, description, linked nodes[]}`
  (`story_beat`, `story_beat_node`; exported in each act's `act.yaml`, part of undo history).
  In acts that have an outline, beats with no linked nodes and nodes in no beat are reported
  (info); books without outlines stay quiet.
- **Wiki mentions:** `[[key]]`, `[[character:key]]` / `[[lore:key]]`, optional `|label`.
  - Mentions are allowed in node beat notes, character text fields, relationship notes,
    lore bodies and beat descriptions.
  - They are indexed in the RefIndex (role `mention`), so they appear as backlinks.
  - A bare key is indexed against both characters and lore. The UI resolves it to a
    character first.
  - Renaming a character or lore key rewrites its mentions, keeping prefixes and labels.

### 2.8 Prose

`ProseVersion {variant_id, text, status: draft|in_review|approved|rejected|superseded,
source: human|llm, pipeline_run_id?, inputs_hash, parent_id, summary, notes, created_at,
approved_at}`.
- **One approved version per variant.** Approving another version supersedes the old one.
  Approving "with my edits" saves a new human version whose parent is the reviewed one.
- **Stale** means the approved version's `inputs_hash` ≠ the hash of the variant's current
  context, minus far-back path summaries. That context covers:
  - beat notes, style, act summary and beats
  - location, characters and mentioned lore
  - the state digest
  - the canonical predecessor's text (its text only, not whether it's approved)
  - the choices
  - the variant's condition

  Changes upstream reach a node one hop at a time, through its predecessor's approved text.
  Stale prose is reported in Problems (`prose_stale`, info).
- **`summary`**: two or three sentences, written by the summarizer; the author can edit it.
  It feeds later sections' "story so far".
- **References:** prose rows refer to nodes and variants softly (no FK), so undo, which
  rebuilds nodes with the same ids, never erases prose history. Undo snapshots don't
  include prose.
- **Git export** carries approved prose (text, summary, inputs hash) in node front matter.

### 2.9 State digest (static analysis)

A forward dataflow analysis over the book graph for one tier (`core/analysis/digest.py`).
It is computed by fixpoint, so loops terminate (the lattice is finite). For each node it
gives the reader's state **on arrival, after on-entry effects**:
- **must**: codewords, items held, characters met and skills that are true on every route.
  This is the intersection over incoming routes.
- **may**: the same kinds of fact, true on some route (the union).
- **reachability**, fewest choices from the start, and most choices from the start (unbounded
  if a loop allows longer routes). Validation reports per-node reachability by itself; the
  digest is also what derives "trapped" warnings.
- **canonical predecessor**: the first node on a shortest route, in choice order. An author
  override is validated as a real predecessor.

**Along each choice**, the analysis adds what the reader *might* do first, as "may":
- optional pickups and shop purchases
- using consumables, which also removes them from must
- selling items

It then adds:
- what the condition proves (`has(rope) and flag(X)` → rope and X are certain afterwards;
  `not flag(X)` → X is absent)
- the choice's effects
- a test's after-effects
- random-table item results on combat choices, as "may"

Choices whose condition no reader can meet contribute nothing, so they don't make anything
reachable either. Further rules:
- A once-only gain on a node or choice inside a loop is only "may" when the book can remove
  that fact.
- Combat outcomes drop consumables, since they can be drunk mid-fight.
- The flee outcome applies the tier's flee cost.
- Codewords set only in other books of the series are "may" from the start.

**Gate verdicts** are three-valued (always / never / depends), using `has`, `flag`, `skill`,
`equipped`, `count(x) >= n` and Boolean connectives. Stat comparisons and `visits()` are
"depends".

**Not tracked:** item counts and stat values.

**Used by:**
- the inspector's **Digest** tab
- validation:
  - `gate_never` (warning) and `gate_always` (info)
  - `unreachable_gated` (warning): reachable only through choices no reader can take
  - `trapped` (warning, reported where readers first get stuck): an ending is reachable on
    paper, but only through choices no reader can take
- the LLM writer and consistency checker (Phase 7+)

Validation runs the digest at the highest tier, where every choice is available.

### 2.10 Playtests

- `PlaytestBatch {book, tier, player, n_runs, seed_base, max_steps, content_hash,
  bundle, status, summary, duration}`:
  - `player` is a bot (`random | greedy | cautious | explorer | completionist`). LLM
    players (`kind: llm, provider_id, model, persona, temperature, max_tokens`, plus the
    batch's `budget_usd`) were added in Phase 9 (ADR 0010).
  - `cost_usd`: what the batch's model calls cost (LLM batches).
  - `bundle` is the exact game bundle played, so runs replay after edits; `content_hash`
    is its SHA-256 (ADR 0008).
- `PlaytestRun {index, seed, outcome: ending kind | max_steps | error, ending node, last
  node, steps, picks[], death_cause, errors}`:
  - `picks` are indices into the available actions at each step, so a run replays
    exactly.
  - `death_cause` is `combat:<enemy>`, `node` (an authored death) or `stat`.
- **Per-step data is reconstructed by replay, not stored.** LLM runs (Phase 8) will
  add stored reasoning and confusion notes per step.
- **Batch summary:** outcomes, win rate, endings, step percentiles, visits and deaths
  per node, act funnel, per-enemy fights/losses/deaths, per-item win-rate lift, coverage
  (nodes, endings, choices), and error samples.
- **Coverage walker:** a bounded BFS over game states.
  - Every choice, pickup, purchase and equip is tried from every distinct situation.
  - Steps that drew dice are re-run with several seeds, and fights are resolved as one
    move.
  - States are deduplicated on what conditions see (node, items, equipment, codewords,
    skills, class, fired once-only effects, visit counts of nodes that conditions
    mention, capped at 4, and the open fight), plus money up to the highest shop price.
  - The result is the set of reachable nodes and endings. It may miss content gated on
    exact stat values.
- **In-app player:** stateless (ADR 0008). The client posts `{tier, seed, class, inputs}`
  and the server replays them. Debug inputs (jump, set state, force the next roll) are
  recorded like moves.

### 2.10a Engine (Phase 3)

`core/engine.Game(book, tier, seed)` plays one book deterministically. State: stats
(+ max for `max_is_initial`), items, equipment slots, flags, skills, class, visits,
once-only keys, shop stock, current combat, ending. Effective stats add item modifiers
(equipment only while equipped; others while carried; `min_tier` respected). Actions:
`choose`, `take` (found items, once), `buy`/`sell` (currency = first resource stat;
sell at the shop's rate), `use` (consumables), `equip`/`unequip`, and in combat
`attack`/`flee`. Entering a node picks the highest-priority matching text variant,
applies on-entry effects, then ends the game on an authored ending (which wins over
stat defeat), or with `stuck` if no choice is available. Content errors (bad
expressions) become `error` events, never crashes. Every step appends JSON-friendly
events; every die is recorded. See ADR 0006 (PCG32 dice, bundles, golden traces) and
ADR 0007 (compiled expressions).

### 2.11 LLM infrastructure

- **Provider profiles**: `name, kind (openai | fake), base_url, api_key_env, models[{id,
  context_window, input/output $ per Mtok}], max_concurrency, timeout, headers`.
  - All are OpenAI-compatible (local, OpenAI, OpenRouter).
  - Keys live only in environment variables (named `…_KEY` or `…_TOKEN`); the API reports
    whether the variable is set. Secret-looking header values are masked in API responses.
  - `fake` is the built-in **offline test model**: deterministic, no network. It is used by
    tests, e2e and demos.
- **Client:** retries 408/409/425/429/5xx and connection errors with exponential backoff
  (honouring Retry-After). If a server rejects `response_format`, the request is retried
  without it.
- **Prompt templates**: Jinja2 (sandboxed, strict undefined), a system prompt and a user
  prompt per role, versioned in the DB and editable in-app, with a live preview against a
  real section.
  - Phase 7 roles: writer, critic, editor, summarizer.
  - Later roles: consistency, suggester, lore-extractor, player.
  - Built-in defaults are seeded as v1.
- **Writing settings** (per series): provider, model, temperature and max tokens per role
  (unset roles use the writer's), pass threshold, maximum rewrites, and a context token
  budget.
- **LLMCall log**: every call — role, template version, model, messages, response,
  tokens, latency, cost, job id. Browsable.
- Structured output via JSON schema (`response_format`), with tolerant parsing (code fences,
  chatter, trailing commas). A bad reply gets one retry with a corrective nudge.
- **Costs** are computed from the model's prices and reported by role, model and day.

### 2.12 Derived & support tables

- **RefIndex** — rebuilt per source on write (a full rebuild must give identical rows; tested);
  targets are matched by key so references to not-yet-created entities resolve once they
  exist. Powers where-used, rename refactors, item totals and codeword usage.
  **Item totals** count supply only: roles `placement`, `shop`, `effect.give`, `table` and
  `loot` (takes, conditions and modifiers are uses, not supply). A shop counts its stock;
  unlimited stock adds nothing to the total but sets an `unlimited` flag (shown as `×N+`).
- **Series entity problems** — enemies, items and tables are validated outside any book by
  running the book validator on an empty probe book in which every entity is available;
  only entity problems are kept (Phase 4).
- **Job** — `kind, status, progress, payload, result, error, created/started/finished`;
  progress streamed via SSE.
- **SectionNumbering** — per book: seed, pins, stable `node/variant → number` map.
- **Checkpoint** — named SQLite snapshot (online backup API).
- **HistoryEntry** — per-book undo/redo stacks of `export_book` snapshots.

### 2.13 Artwork & maps

**Asset** (series library): `{id, series_id, filename, mime, width_px, height_px, bytes,
sha256, alt_text, caption, credit, licence, tags[]}`.
- **Formats:** PNG, JPEG and WebP. SVG comes later, once it can be sanitised.
- **Storage:** content-addressed files under `<data_dir>/assets/<sha256>.<ext>`, not in
  SQLite. Identical uploads are deduplicated.
- **Thumbnails:** generated on upload with Pillow.
- **Garbage collection:** files are removed only when no row *and no checkpoint* references
  them.
- **References:** assets are indexed in the RefIndex, so the library shows where each is
  used and refuses to delete an asset in use (unless forced).

**ArtPlacement**: where artwork appears.
- **Fields:**
  - `{target, asset?, role, layout, brief, status, caption?, tier?/variant?, media}`
  - `media` is one of `print | digital | both`.
  - `asset` may be empty: a **placeholder** with an art brief, so books can be laid out
    before the art exists.
- **Commissioning status:** `needed | sketch | final`. The commissioning tracker lists every
  placement with its brief, target size and status, and exports a shot list (Markdown/CSV)
  for illustrators.
- **Targets and roles:**
  - Node: `illustration`. Several per node are allowed, and a placement can be limited to one
    text variant.
  - Act: `opener`, a full-page piece at the start of an act, with the act title over it or
    facing it.
  - Book: `cover_front`, `cover_back`, `frontispiece`, `title_page`, `endpaper`.
  - Character, enemy, item and lore entry: `portrait` / `image`, used by the lore pages,
    appendices and the player's codex.

**Print layout controls** (per placement; previewed in the proofing view):
- **Size:**
  - `full_page`, with an option to bleed off the trim edges
  - `full_width` (the text block)
  - `half` (½ text width)
  - `third`
  - `vignette`: a small spot illustration of about 25–35 mm
  - `custom`: width in mm, or as a percentage of the text block
  - A maximum height in mm caps tall images in every mode.
- **Position:**
  - `before_text` or `after_text`
  - `after_paragraph: N`
  - `own_page`, with recto/verso preference
  - `facing_page`, opposite the section's text
  - Act openers default to a recto full page.
- **Alignment / wrap:** `left | right | center`. Half, third and vignette sizes can have text
  wrap around them, with a gutter in mm.
- **Crop:** a focal point (x, y) and an optional aspect ratio (`original`, `1:1`, `4:3`,
  `3:2`, `2:3`, `16:9`). The printed crop is derived from these, never by destroying the
  original.
- **Keep-with:** a node illustration stays on the same spread as its section number. If it
  can't fit, the compiler reports a layout warning rather than moving the section.
- **Resolution check:** effective DPI = pixels ÷ (printed size in inches).
  - Below 300 DPI is a warning; below 150 DPI is an error for print exports.
  - Full-page bleed requires the image to cover trim plus bleed.
- **Digital is set separately:** `full_width | inline | thumbnail`, plus whether a tap opens
  the full-size image. Print sizes don't constrain the digital player.

**Map**: `{key, title, book scope, asset, markers[]}`.
- Each marker is `{x, y (0–1), label, links to a node or lore location, visible_if?: gbx condition}`.
- **Print:** maps appear as act openers, appendix pages or full-page placements.
- **Digital player:** an interactive map. Markers link to codex entries, and can be revealed
  by codewords.

As built (Phase 10, ADR 0011):
- **Assets:**
  - Uploads are the raw request body, up to 40 MB and 160 Mpx.
  - Pillow checks the format (PNG, JPEG or WebP) and makes a 480 px WebP thumbnail.
  - Files live at `assets/<sha256>.<ext>`; rows are deduplicated per series.
  - GC (`POST /assets/gc`, and after asset deletes, series deletes and import replaces)
    keeps any hash named by a live row or by the `asset` table of any checkpoint, and any
    file touched in the last 15 minutes. An unreadable checkpoint aborts GC.
  - Imports take an image's type and size from the image itself, never from `assets.yaml`.
    Files are served with `nosniff`.
- **Placements** (`art_placement`):
  - One table, with a nullable foreign key per target kind (`node_id`, `act_id`, `book_id`,
    `character_id`, `enemy_id`, `item_id`, `lore_id`) and `target_type`.
  - Deleting the target cascades; deleting the image sets `asset_id` to NULL, leaving a
    placeholder.
  - Node, act and book placements are part of the book's undo history.
  - Placements and maps are RefIndex sources whose targets are `asset` rows (keyed by id),
    which powers where-used and the delete guard.
- **Page setup:** `book.print_setup` holds trim, margins and bleed in mm. The default is a
  6×9 in trim with 1/8 in bleed.
- **Print sizes:**
  - Image size presets are relative to the text block (`core/art.py`). An image fills its
    box's width, shrinking to fit the box height and the maximum height.
  - Full-bleed art covers trim + bleed on the three outer edges.
  - Effective DPI is computed on the cropped pixels.
  - A placeholder is drawn as a 4:3 box.
- **Problems:**
  - `art_low_dpi`: a warning below 300 dpi, an error below 150.
  - `art_bleed`: an error.
  - Info: `art_placeholder`, `art_alt_text`, `asset_unused` and `map_no_image`.
  - `map_marker_broken`: a warning.
- **Maps:** the book is optional (none means series-wide). Markers live in a JSON list,
  each with `{id, x, y, label, node_id?, lore_id?, visible_if?}`. The player shows only the
  markers whose condition holds, and flags the one at the reader's section.

### 2.14 Appendices (generated back matter)

`Appendix {book, kind, title, position, enabled, options}`.
- The pages are rendered from live data with the same HTML templates in the in-app
  preview, print/EPUB and the digital player (as a codex).
- Every appendix is **tier-aware**: a Basic edition shows Basic stats only.
- Every appendix has a **spoiler policy**:
  - `all`, or `met_on_canonical_path`
  - `hide_key_items`
  - `blank_entries`: names with blank stat boxes for the reader to fill in

**Kinds:**
- **Bestiary**
  - Contents: every enemy appearing in the book (via encounters and random tables), with
    portrait, description and lore link.
  - Stat blocks are given per tier, at the levels used in the book, or as a level table.
  - Order: alphabetical or by first appearance in canonical order.
- **Adventure sheet / stat sheet:** generated from the tier's player stats.
  - Boxes for initial, current and maximum values; class and skills checkboxes.
  - Inventory slots and an equipment-slot table; a currency box.
  - Codeword tick list (or blank lines); provisions and notes.
  - Printed as a front- or back-matter page; also a printable PDF on its own.
- **Item catalogue / inventory:** name, category, slot, modifiers per tier, use effects and
  value, with optional images. Key items can be hidden.
- **Rules quick reference:** the tier's test and combat procedures, damage hooks and flee
  rules, condensed from the rule system and its rules-chapter text.
- **Dramatis personae** (characters) and **glossary** (lore entries of type glossary).
- **Maps:** each map as a full page, with a marker legend.
- **Custom page:** Markdown with `[[mentions]]` and artwork, for an author's note, credits
  and the like.

As built (Phase 10):
- **Rendering:** each kind renders through `gamebook/render/templates/appendix/<kind>.html`,
  which is autoescaped. Author Markdown in custom pages, rules text and glossary entries
  uses a small safe subset (`render/markdown.py`): it escapes everything else, with no raw
  HTML, links or images.
- **Previews:** `GET /appendices/{id}/render` returns a fragment and a standalone document.
  The app shows the document in a sandboxed iframe.
- **Tier:** the default is the highest tier.
- **Spoilers:** `met_on_canonical_path` keeps nodes on canonical-predecessor chains from
  the start to each reachable victory, or every reachable node if the book has no victory.
- **Codex:** `POST /books/{id}/codex {tier, enemies, items}` returns the enabled
  appendices except adventure sheets. The bestiary and items list only what the reader has
  met, which the player reports in `PlayOut.codex`.

## 5. LLM Pipelines

### 5.1 Context assembly (shared)

For a node variant: series style guide (+ book/node overrides) · act summary + linked beats ·
beat notes · location & character lore · **state digest** (must/may) · canonical path
**rolling summary** (each approved node stores a 2–3 sentence summary; the chain is
compressed beyond N hops) · canonical predecessor's full approved text · outgoing choice
labels (prose must set them up) · encounter/item *names* (no numbers — mechanics are
rendered separately). Token budget manager trims lowest-priority context first.

As built (Phase 7):
- **Story so far:** up to 8 approved summaries back along the canonical path.
- **Predecessor text:** when the predecessor has no approved text, its newest draft is used,
  marked "(unapproved draft)", so batch writing can build section on section.
- **Token estimate:** about 4 characters per token.
- **Trim order** when over budget: mentioned lore, then the oldest story-so-far entries,
  beats, character details, the location text, and finally the start of the previous
  section. Beat notes, choices, digest and style are never cut.

### 5.2 Writer → Critic → Editor loop

1. **Writer** drafts prose.
2. **Critic** returns structured JSON: rubric scores (beat adherence, continuity,
   path-validity vs. state digest, style compliance, choice setup, prose quality) +
   concrete issues with quotes.
3. If below threshold and iterations remain, **Editor** rewrites addressing the issues → 2.
4. Result lands as `in_review` with the full critique trail for the author.
5. **Summarizer** writes the section's 2–3 sentence summary.

Each run is a `PipelineRun {trail[draft|critique|edit], iterations, final_score, cost}`,
and every model call is in the log.

"Write an act" runs the loop for each selected section in canonical order (act, then
distance from the start), as one job. It can be limited to missing or stale sections and
capped by a budget.

### 5.3 Assist pipelines

- **Consistency checker** (per node / act / book): contradictions between prose, lore,
  state digest and mechanics ("text mentions the sword you can't have here").
- **Beat/branch suggester**: from an act outline + current graph, proposes nodes/choices
  as a *draft subgraph* the author can accept piecemeal.
- **Lore extractor**: from approved prose, proposes new/updated characters & places as drafts.

As built (Phase 8), each assist is a job that leaves `AssistItem` rows for the author:
- **Consistency checker**
  - Reads a variant's prose (approved, else the newest draft) with its assembled context and
    the "only some readers have" facts.
  - Returns findings: `{severity, category (path_validity | lore | continuity | mechanics),
    quote, problem, suggestion}`.
  - Open findings appear in the Problems panel (`consistency`) until the prose changes; then
    they show as outdated. A re-check replaces the variant's open findings; findings can be
    dismissed.
  - Runs per section, per act, or for the whole book (sections with prose only).
- **Suggester**
  - Reads the act's beats (marking those with no sections) and its existing sections and
    choices, plus author notes.
  - Returns new sections (`ref`, title, beat notes) and choices between existing keys and new
    refs. Malformed sections and choices are dropped, as are choices with an unknown end and
    choices between two existing sections.
  - Shown as dashed **ghost** cards and edges on the canvas.
  - The author adds sections and choices one at a time or all at once. Adding a choice also
    adds any new section at its ends.
  - New sections are placed to the right of their source and moved down past existing cards
    (the ghosts use the same rule). Accepting is a single undo step.
- **Lore extractor**
  - Reads approved prose (up to about 24k characters) against the existing wiki.
  - Proposes new characters and entries, or new facts for existing ones (`existing_key`),
    each with quoted evidence.
  - The author edits a draft, then creates the entry or appends the new text to the existing
    one. Open drafts aren't proposed twice.
- **Models:** the three new roles (`consistency`, `suggester`, `lore_extractor`) have
  versioned templates and per-series models like the prose roles. Unset roles use the
  writer's model.

### 5.4 LLM player

Sees only what a reader sees: rendered page (prose + mechanics block for the tier),
adventure sheet, choice list. Responds with JSON `{choice, reasoning, confusion?}`. The
engine rolls all dice — the model cannot cheat. Personas: cautious, reckless, completionist,
role-player. Memory: rolling self-summary to bound context.

As built (Phase 9, ADR 0010):
- **Page** (`core/sim/reader.py`): approved prose for the reader's variant, else the beat
  notes, else "(This section has no text yet.)". Then:
  - "What just happened": narrated events, including dice.
  - The adventure sheet: player stats with caps, class, skills, items, equipped, codewords.
  - Any fight in progress.

  Options are numbered separately. No titles, keys or conditions.
- **Protocol:** the `player` role (an editable template) answers with
  `{choice, reasoning, memory, confused, confusion}`.
  - Invalid JSON is re-asked once (`call_json`). An out-of-range choice is re-asked once.
  - A run whose model call still fails ends as `llm_error`. Three in a row halt the batch
    as `failed`.
  - Page text is capped at 12k characters, options at 200. Content-error events are never
    shown.
  - Memory is the model's own summary (≤ 600 characters). Notes are clipped to 500.
- **Batches:** `BatchIn.player` is a bot or `{kind: "llm", provider_id, model, persona,
  temperature, max_tokens}`.
  - A player with no `kind` is treated as a bot.
  - Caps: 200 runs and 400 steps. `budget_usd` is optional.
  - Games run in parallel (≤ 4, and no more than the provider's concurrency) on the job
    runner's separate `llm` lane. Each run is saved as it finishes.
  - The batch's cost is a running total, updated per call.
  - The batch ends `done`, `stopped` (budget reached), `cancelled` or `failed`.
- **Resume:** `POST /batches/{id}/resume {budget_usd?}` plays the missing, stopped and
  `llm_error` runs.
- **Results:**
  - Runs carry `notes` per step and `cost_usd`. Replays return the `next_note` for the
    step shown.
  - The summary adds `llm`: steps, confused steps, cost, stopped runs, and confusion by
    node with sample notes.
  - Every call is in the LLM call log (role `player`), scoped to the book and job.

## 6. Export

### 6.1 Git tree (round-trip)

```
series.yaml  style.yaml  rules/<system>.yaml  enemies/<key>.yaml  items/<key>.yaml
tables/<key>.yaml  lore/characters/<key>.md  lore/<type>/<key>.md
books/01-<slug>/book.yaml  books/01-<slug>/acts/01-<slug>/act.yaml
books/01-<slug>/acts/01-<slug>/nodes/<key>.md   # YAML front-matter + prose per variant
```
Deterministic ordering and formatting; `import` rebuilds the DB; round-trip is a CI test.

Assets export as `assets/<sha256>.<ext>` plus `assets.yaml` (metadata). Placements, maps and
appendices are exported with their owners (node front matter, `act.yaml`, `book.yaml`,
`maps/<key>.yaml`). Large binaries may use git LFS (documented, not required).

### 6.2 Game bundle (digital player)

Validated, self-contained JSON for one book + tier set. Versioned schema. The bundle zip
also carries the artwork used by digital placements, maps and the codex, resized for
screens.

As built (Phase 12, ADR 0013):
- **Export:** Export → **Build web player** (`POST /books/{id}/print/exports {format: "web"}`)
  produces a zip containing:
  - the prebuilt player (`frontend/dist-player`, one classic script, so it runs from
    `file://`)
  - `book.js`, which sets `window.GAMEBOOK` (format `gamebook-player` v1):
    - the game bundle (`gamebook-bundle` v1)
    - approved prose per variant, with beat notes as a marked draft where a section has
      no prose
    - digital art scaled to 1600 px
    - maps with markers and their `visible_if`
    - for every tier, the enabled appendices except the adventure sheet, as full HTML
      documents (bestiary and item entries carry `data-enemy` / `data-item` keys)
  - `manifest.webmanifest`, `sw.js` (cache-first offline play over HTTPS) and an icon
- **Engine:** the player runs the TypeScript port (`frontend/src/engine`). Parity with the
  Python engine is enforced by:
  - replaying the golden traces
  - a generated corpus (`backend/tests/core/parity_corpus.py` → 48 bot games across
    tiers and seeds, including a book with content errors), compared by final state and
    a SHA-256 of the canonical event JSON
  - `tests/core/test_parity_corpus.py`, which fails when the Python engine changes
    without the corpus being regenerated
  - shared limits: gbx tokens are ASCII-only, and integer results beyond 2^53 are an
    error ("number too large") in both engines
- **Player:**
  - **Title screen:** cover, edition (tier) and class choice, and save slots (the
    autosave plus up to 20 named saves in `localStorage`). A save is `{tier, seed,
    class, moves}` and is restored by replaying it.
  - **Play screen:** art (by variant and tier, with tap to zoom); prose or draft notes;
    what happened (narrated events); combat; choices, with disabled ones and their
    reasons; items and shop actions; Back (undo); Save; endings.
  - **Side panels:** the adventure sheet, maps (markers shown when their condition
    holds, "you are here") and the codex. Unmet bestiary and item entries are hidden by
    CSS injected into a sandboxed frame.

### 6.3 Print / EPUB

- **Section numbering**: seeded shuffle with pins (1 = start, etc.), stored map keeps
  numbers stable across re-exports; "reshuffle" is explicit.
- **Compilation**: text variants and non-printable state become split sections, tick boxes
  or codewords; gated choices render "If you have…, turn to N"; combat/test blocks rendered
  per tier.
- **Editions**: one edition per tier, or a combined edition with tier-marked blocks
  (open question, §8).
- Front matter: rules chapter for the tier, adventure sheet, character creation.
- **Artwork:** print layout controls (§2.13), recto act openers, cover and frontispiece,
  bleed and trim, and DPI checks.
- **Back matter:** the book's enabled appendices (§2.14), in their configured order.
- PDF via HTML/CSS templates (WeasyPrint); EPUB with internal links (ebooklib); both share
  templates.

As built (Phase 11, ADR 0012):
- **Editions:** one per tier, which settles the open question below. The edition's tier
  sets the stats, tests, combat, tier-limited choices, the rules chapter and every
  appendix.
- **Numbering** (`core/printbook/numbering.py`):
  - Each act gets a consecutive block of numbers. Sections are shuffled within it using
    the book's `print_seed`.
  - Pins are honoured inside their act's block; the start section is 1 unless something
    else is pinned to 1.
  - The map (`book.print_numbers`) keeps every number that still fits, so adding a
    section doesn't renumber the rest.
  - **Reshuffle** picks a new seed and clears the map.
  - Section keys are `n:<node>` (the entry), `v:<variant>` and `p:<node>` (the plain
    fallback).
- **Compiler** (`core/printbook/compile.py`):
  - **Text variants:** a node with them gets a *router* section (conditions in the
    engine's priority order, evaluated on arrival before on-entry effects), then one
    section per variant. Each variant section repeats the mechanics.
  - **Tick boxes:** `visits()` gives the node one tick box per visit its conditions
    need. Once-only gains and found items in revisitable nodes (nodes on a cycle) get a
    box and "first box" phrasing.
  - **Choices:** gated choices read "If …:"; rolls print their bands; tests print the
    roll, the success rule and after-effects; fights print stat blocks at the encounter
    level for the edition, or the roll table (non-fight results count as a win); flee
    prints its cost.
  - **Machine-checkable output:** every section carries `links` (choice, outcome →
    number) and `routes` (variant → number).
- **Verifier** (`core/printbook/verify.py`):
  - Bots play the engine. Every outcome must be printed in the reader's current section
    with the engine's destination number, every router must route to the engine's
    variant, and authored endings must print an ending.
  - Structural checks: numbers are 1..N, and every "turn to" points at a section that
    exists.
  - Static checks against the engine's own rules (`Game.tier_allows`): routers list the
    variants in the engine's order, sections print exactly the choices and effects the
    engine applies in this edition, endings match, and the begin page names the start's
    number.
- **Layout:**
  - **Front matter:** cover, endpaper, frontispiece (verso), title page, then character
    creation. The rules chapter and adventure sheet come next, unless the book has
    enabled appendices of those kinds.
  - **Body:** "turn to 1", then the sections in number order, each act starting on a
    recto with its opener, then back matter (the enabled appendices) and the back cover.
  - **Art in sections:** placed by position (before or after the text, after paragraph
    N, own or facing page) and size; wrap floats with a gutter; a full-page bleed uses a
    zero-margin page.
  - **PDF:** WeasyPrint with mirrored margins, bleed and crop marks, loading files only
    from the asset store. Page anchors give keep-with and facing-page warnings.
- **EPUB 3:** written directly with no extra library. It contains front matter, sections
  in chunks of 40 files, back matter, a nav, and digital art scaled to 1600 px. Pages are
  XHTML (via tinyhtml5).
- **API:**
  - `GET /books/{id}/print/preflight?tier` and `GET /books/{id}/print/preview?tier`
    (the proof, served with CSP).
  - `POST /books/{id}/print/reshuffle`, `POST /books/{id}/print/verify`.
  - `POST /books/{id}/print/exports {tier, format}` runs a job; `GET /print/exports/{job}`
    downloads the result. The 20 newest exports are kept.

## 7. Validation Rules (initial set)

| Rule | Severity |
|---|---|
| Book has exactly one start node; it is reachable-root | Error |
| Non-final act has ≥1 exit; acts after the first have ≥1 entry | Error |
| Cross-act choice not exit→entry of next act | Error |
| Outcome missing target / target in another book | Error |
| Roll/table ranges don't cover the dice range, or overlap | Error |
| gbx parse/type error, unknown reference, stat inactive in tier | Error |
| Enemy missing formula for an active tier stat | Error |
| Node has no outgoing choices and no ending | Warning ("unmarked dead end") |
| Node unreachable from start | Warning |
| Gated choice never / always satisfiable (state digest) | Warning / Info |
| Node can't reach any ending | Warning |
| Cycle without a state change on the loop (possible softlock) | Warning |
| Non-printable construct with no compile strategy | Warning |
| Beat with no nodes / node in no beat | Info |
| Prose stale / missing | Info |
| Artwork below 300 DPI at its printed size (below 150: error for print) | Warning / Error |
| Full-page bleed artwork smaller than trim + bleed | Error (print) |
| Art placement with no asset (placeholder) / no alt text | Info |
| Map marker linking a deleted node or lore entry; asset unused in the library | Warning / Info |
